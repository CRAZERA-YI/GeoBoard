# 优化说明（阶段 07）

## 结论：本版本**未做**额外性能优化，依据是实测数据表明无需优化

阶段 07 的规范是"先测量，再优化"（见 `qt5_skill/workflow/stages/07_optimize/optimization.md`）。
本文件记录的是**测量结果与"不优化"的判断依据**，而不是一次优化过程。
06 阶段的自动化测试已通过，因此本阶段的前提成立。

## 1. 优化目标与测量方法

| 目标 | 现状（测量值） | 期望 | 怎么测 |
|---|---|---|---|
| 拖动自由点后的依赖子图重算 | **0.0700 ms/次**（200 次共 14.0 ms；连跑 4 次的波动区间 0.0700–0.0850） | < 50 ms（需求验收标准） | `scripts\build.bat test` 运行 `geometry_smoke.exe` 的性能基准，Release 构建，`QElapsedTimer` 计时 |
| 命中测试（每次鼠标移动都会调用） | **0.1080 ms/次**（2000 次平均；波动区间 0.1080–0.1120） | < 5 ms | 同上 |
| 测试规模 | 991 个图元（330 节深层依赖链） | 1000 图元量级 | 同上 |

余量：重算约 700 倍、命中测试约 45 倍。原始输出见 `docs/test.md`。

## 2. 已做的优化

**本阶段没有新增优化。** 下列措施是编码阶段就按设计文档落地的结构决策，
上表的实测数据正是它们的结果，列在这里是为了说明"为什么不需要事后优化"：

| # | 措施 | 依据 | 效果 |
|---|---|---|---|
| 1 | 只重算受影响的**子图**，不做全量重算 | `docs/design.md` 决策 D5 | 拖动 991 图元中的一点，只重算它的传递依赖者 |
| 2 | 维持"父 id < 自身 id"不变式，免去运行时拓扑排序 | 决策 D3 | 重算退化为一次线性扫描 + 一次升序排序 |
| 3 | 拖动期间用 `beginUpdate()`/`endUpdate()` 批量提交 | `GeoDocument` 接口约定 | 一次拖动只发一次 `documentChanged`，避免每个中间状态都全画布重绘 |
| 4 | 几何由点位 id 导出、不缓存坐标 | 决策 D2 | 无同步开销，也不存在"忘了同步"的返工 |
| 5 | 无界直线先裁剪到可见矩形再绘制 | `CanvasWidget::drawLineData` | 避免坐标溢出与无效绘制 |
| 6 | 圆弧按屏幕弧长自适应采样（上限 256 段） | `CanvasWidget::drawArcData` | 放大后弧仍平滑，且绘制量有上界 |

## 4. 结论与未采纳的方案

| 方案 | 不采纳的原因 |
|---|---|
| 命中测试引入空间索引（四叉树 / 网格） | 991 图元下实测 0.11 ms，距 5 ms 指标有 45 倍余量；引入索引会增加"图元移动后索引失效"这一整类 bug 的风险，收益与风险不成比例 |
| 绘制使用 QPixmap 缓存 | 1000 图元量级下全量重绘已足够；缓存会引入"何时失效"的复杂度 |
| 把 `shapesInOrder()` 的排序改为增量维护 | 排序 1000 个整数远小于一次重算的成本，实测未构成瓶颈 |
| 多线程重算 | 重算已在 0.07 ms 量级，线程调度与同步开销大于收益；且会引入跨线程访问 UI 的风险（skill 明确禁止在子线程操作 QWidget） |

## 5. 何时应回来做这一阶段

出现下列任一情况时重新评估（并先测量）：

- 单文档图元数稳定超过 5000 且出现拖动卡顿；
- 命中测试单次超过 1 ms；
- 新功能使拖动重算超过 5 ms（例如引入约束求解器、轨迹追踪）。

## 6. 与性能无关的手感问题（不属本阶段）

平移/缩放后测量标注位置不跟随图形（见 `docs/delivery.md` 缺陷 T1）是**设计缺陷**，
不是性能问题，修它不需要优化阶段。
